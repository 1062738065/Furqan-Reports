# نظام توثيق الأداء — جمعية فرقان

نظام React لتوثيق التقارير الدورية للأداء، خاص بجمعية فرقان لتحفيظ القرآن الكريم بالطائف.

## التشغيل محليًا

```bash
npm install
npm run dev
```

بعدها افتحي الرابط اللي يظهر بالطرفية (عادة `http://localhost:5173`).

## رفع المشروع على GitHub

1. أنشئي مستودع جديد على GitHub باسم **Furqan-Reports** بالضبط (نفس الاسم مهم لأن إعداد Vite مربوط فيه).
2. ارفعي كل ملفات هذا المجلد للمستودع:

```bash
git init
git add .
git commit -m "النسخة الأولى من نظام توثيق الأداء"
git branch -M main
git remote add origin https://github.com/<اسم-حسابك>/Furqan-Reports.git
git push -u origin main
```

## تفعيل GitHub Pages (خطوة تسوّى مرة وحدة بس)

1. روحي لصفحة المستودع على GitHub → **Settings** → **Pages**.
2. تحت **Build and deployment** → **Source**، اختاري **GitHub Actions** (مو "Deploy from a branch").
3. كذا خلاص — أي مرة تدفعين (`push`) على فرع `main`، الموقع يتبنى وينشر تلقائيًا عن طريق ملف `.github/workflows/deploy.yml` الموجود بالمشروع.

بعد أول نشر ناجح، الموقع يكون متاح على:

```
https://<اسم-حسابك>.github.io/Furqan-Reports/
```

## النشر اليدوي (بديل اختياري)

إذا ما بتستخدمين GitHub Actions ولك سبب معيّن، فيه طريقة يدوية جاهزة عن طريق حزمة `gh-pages`:

```bash
npm run build
npm run deploy
```

هذي الطريقة تبني المشروع وتنشره مباشرة على فرع `gh-pages`. في هالحالة، لازم تغيّرين مصدر GitHub Pages بالإعدادات إلى **Deploy from a branch** واختيار فرع `gh-pages` بدل GitHub Actions.

## بنية المشروع

```
Furqan-Reports/
├── index.html              نقطة دخول Vite
├── package.json
├── vite.config.js          يحدد base: "/Furqan-Reports/" (لازم يطابق اسم المستودع)
├── .github/workflows/
│   └── deploy.yml          نشر تلقائي على GitHub Pages
└── src/
    ├── main.jsx            يشغّل تطبيق React
    ├── App.jsx             نظام توثيق الأداء كامل (بدون أي تعديل)
    └── index.css           تنسيق أساسي بسيط
```

## ربط النظام بقاعدة بيانات Google Sheets

النظام الآن مجهّز للاتصال بجدول Google Sheets كقاعدة بيانات حقيقية مشتركة بين كل الأجهزة (نفس أسلوب نظام المقاصف)، عبر ملف `Code.gs` الموجود في هذا المجلد.

### خطوات الربط

1. أنشئي جدول بيانات (Google Sheet) جديد فارغ في حسابك.
2. من القائمة: **الإضافات (Extensions) → Apps Script**.
3. احذفي أي كود موجود، والصقي محتوى ملف `Code.gs` بالكامل مكانه، ثم احفظي (Ctrl+S).
4. من قائمة الدوال أعلى المحرر اختاري الدالة **setup**، ثم اضغطي **تشغيل (Run)**.
   - أول مرة سيطلب صلاحيات — اختاري حسابك ثم "متابعة" ثم "الانتقال إلى ... (غير آمن)" ثم "السماح".
   - هذا ينشئ تلقائيًا ورقتين: **"البيانات"** (تخزّن كل بيانات النظام) و**"المستخدمون"** (حسابات الدخول).
5. **Deploy → New deployment** → اختاري النوع **Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
   ثم اضغطي **Deploy** وانسخي رابط **Web app URL** الذي يظهر.
6. افتحي `src/App.jsx` وابحثي عن السطر:
   ```js
   const REPORTS_API_URL = "PUT_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
   ```
   واستبدلي النص بالرابط الذي نسختِه، ثم احفظي وارفعي المشروع (git push) كالمعتاد.
7. في ورقة **"المستخدمون"** بالجدول، أضيفي صفوف الحسابات الحقيقية بنفس ترتيب الأعمدة الجاهزة (اسم المستخدم، كلمة السر، الاسم، الصلاحية: admin أو user، معرف الوحدة). معرّف الوحدة يجب أن يطابق `id` الوحدة كما يظهر داخل النظام من "إدارة الأقسام والوحدات".

بعد هذه الخطوات، كل حفظ داخل النظام (الأقسام، المؤشرات، الأهداف، تقارير الوحدات...) يُكتب مباشرة في ورقة **"البيانات"** بجدولك، وأي مستخدمة تدخل من أي جهاز أو متصفح ترى نفس البيانات فورًا.

> ملاحظة: لو ما رُبط الرابط بعد (تُرك كما هو `PUT_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE`)، يستمر النظام بالعمل تمامًا كما كان — يحفظ محليًا في المتصفح فقط، وحسابات الدخول التجريبية (`admin`/`admin123`) تبقى تعمل — حتى لا ينكسر شيء قبل إتمام الربط.

### ملاحظة أمنية

كلمات السر تُحفظ في ورقة "المستخدمون" كنص عادي (نفس أسلوب نظام المقاصف)، فحافظي على أن مشاركة الجدول محدودة لمن تثقين بهن فقط.
